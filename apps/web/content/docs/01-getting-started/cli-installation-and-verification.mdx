## 当前可用性

当前 Preview contract 将结构化 CLI JSON 标记为 `unavailable`。因此本网站没有可下载的 `ShaderPackCli` 二进制、固定命令名、稳定参数或可复制的生产 JSON 输出。文档不会伪造一个安装包，也不会把网站仓库的 schema 校验结果写成 Loader 已通过。

这意味着当前作者可以完成：

- 使用 contract 中的 schema 做 `schema-only` 检查；
- 在自己的 Core 构建中运行 Loader 或 smoke test；
- 保存真实的退出码、诊断码、Core commit 和输入 hash。

但当前作者不能从本网站下载一个已发布、版本化并带稳定 JSON contract 的 CLI。

## Core 本地构建

如果你已经取得 DawnlightCore 源码，可以在仓库根目录构建 Windows 目标：

```powershell
dotnet build ./Survivalcraft.Windows/Survivalcraft.Windows.csproj -c Debug
```

这条命令构建的是 Core/游戏目标，不等于网站已经发布了独立 CLI。构建完成后，应依据该 commit 的实际工具入口运行 Loader 验证；不要猜测命令名称或把 Debug 输出目录直接上传为 release artifact。

## 验证顺序

1. 使用 `schemas/shaderpack.schema.json` 校验 `shaderpack.json` 和 fragments；
2. 使用对应 Settings UI schema 校验 authored UI 文件；
3. 在同一 Core commit 上运行本地 Loader smoke test；
4. 检查 `UnknownIdentifier`、`DuplicateRegistration`、`UnsupportedVersion` 等机器诊断；
5. 对输入文件计算 hash，并记录验证环境和退出码；
6. 只有 schema、Loader、资源和发布元数据都通过后，才可以进入 Release Feed。

## 可复现记录

建议在光影包仓库保存如下结构。字段名称是网站推荐的记录格式，不表示当前 CLI 已经提供同名 JSON 输出：

```json
{
  "contractVersion": "preview-2026-08-16",
  "coreCommit": "<40-char-commit>",
  "packVersion": "<pack-version>",
  "tool": {
    "name": "<actual-loader-or-cli-name>",
    "version": "<actual-version>"
  },
  "checks": [
    { "kind": "schema", "status": "passed" },
    { "kind": "loader", "status": "passed" }
  ],
  "exitCode": 0,
  "diagnostics": [],
  "inputs": [{ "path": "shaderpack.json", "sha256": "<64-lowercase-hex>" }]
}
```

如果 Loader 尚未运行，应明确写成 `schema-only`，并删除或标记 `loader` 检查，不能保留一个看起来像成功的占位结果。未来正式 CLI 发布后，本页需要随 CLI 版本、安装渠道和 JSON schema 一起更新。
