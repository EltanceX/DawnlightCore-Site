# ADR-0001：V1 范围与静态发布

状态：已冻结

日期：2026-08-16

相关文档：[V1 实施方案](../DawnlightCoreWebsiteV1ImplementationPlan.md)

## 背景

DawnlightCore 网站未来需要支持开发文档、官方下载、光影项目、用户上传、验证和审核。当前网站仓库刚建立，社区 API、账户、数据库和上传验证尚未存在；Core 的公共 ABI 也还在演进。

如果第一版直接建设社区后端，会同时引入身份、对象存储、审核、队列和安全边界，拖慢最有价值的两个任务：开发者阅读规范和玩家正确下载文件。

## 决策

V1 只发布一个静态开发者门户和官方下载站：

- 前端使用 Next.js App Router、Fumadocs、TypeScript strict；
- 生产构建使用 static export，输出可以部署到任意静态 CDN/对象存储；
- 文档、发布清单、搜索索引和 Core contract snapshot 在构建期解析；
- 不启动 NestJS API、数据库、队列、登录、社区浏览或用户投稿；
- 大型安装包和光影包不经过网站服务器转发；
- 首页、文档、下载和发布详情全部从经过验证的仓库 source 生成；
- 未来 API/Worker 仍放入同一个 pnpm workspace，但在真正需要前不创建空服务。

## 选择理由

静态发布能够：

- 减少 V1 运行时故障面；
- 让国内/全球部署可以在 CDN、对象存储和静态托管之间迁移；
- 使文档版本和 release feed 内容可复现；
- 让网站不接触用户上传和不可信 GLSL；
- 在社区后端成熟前先验证开发者和下载用户体验。

## 影响

V1 不提供动态下载计数、用户登录、在线校验和项目投稿。所有这些能力进入后续阶段时，必须遵循总体开发文档中的 NestJS/Fastify、PostgreSQL、对象存储和隔离 Validator Worker 方案，而不是通过临时 Route Handler 绕过边界。

## 退出条件

只有在以下条件满足后，才允许把 V1 变为动态社区产品：

- 通过单独 API/数据模型 ADR；
- 完成上传威胁模型和隔离验证 Worker；
- 具备内容政策、许可证规则和审核流程；
- 维护者录入目录已验证兼容性数据模型；
- 静态 release feed 和 V1 artifact 组件已有稳定版本合同。
